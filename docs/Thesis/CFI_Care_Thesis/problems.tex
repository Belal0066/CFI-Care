\section{Problems Faced During the Project}

% Initially, we encountered connectivity issues between the router and the cloud.

% The router was unable to ping the cloud, and similarly, the cloud could not ping the router.

% To investigate, we monitored ARP activity. The cloud was repeatedly sending ARP requests in an attempt to discover the router's MAC address. Although the router responded with ARP replies, these replies did not reach the cloud. As a result, the cloud failed to learn the router’s MAC address. This led us to suspect that the problem was with the cloud’s interface.

% To confirm this, we added a second router (R2) to the topology and tested connectivity between R1 and R2. The ping test between the two routers succeeded, confirming that the issue was isolated to the cloud interface.

% We then focused on the Microsoft Loopback Adapter, which was the interface connected to the cloud in GNS3.

% To resolve the issue, we took the following steps:

% \begin{itemize}
%     \item Temporarily disabled the Windows Defender Firewall.
%     \item Uninstalled \texttt{Npcap}, which had been installed by default.
%     \item Installed \texttt{WinPcap}, known for more stable integration with the GNS3 cloud.
% \end{itemize}

% After these changes, connectivity was successfully restored. Both the router and the cloud were able to ping each other.

% \textbf{Note:} The cloud was connected via \texttt{Loop1}, which corresponds to the Microsoft Loopback Adapter on our host system.
