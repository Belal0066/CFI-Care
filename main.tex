\section{Objectives}

\subsection{Lab Reports Summarization Objectives}
The primary \textbf{objective Pathalogy Reports Summarization} of this project is:\\
Automate the extraction and summarization of laboratory reports, enabling doctors to quickly review key findings without manually reading lengthy documents, while maintaining data privacy and compliance with HIPAA and FHIR standards.

\subsection{Security Objectives}
The primary \textbf{security objectives} of this project are:

\textbf{Authentication \& Access Control:}
\begin{itemize}
    \item Implement robust multi-factor authentication (MFA) using industry-standard protocols
    \item Establish role-based access control (RBAC) for patients, doctors, and caregivers
    \item Deploy OAuth 2.0 and OpenID Connect for secure authorization and authentication flows respectively
    \item Ensure secure session management and token handling
\end{itemize}

\textbf{Data Protection \& Encryption:}
\begin{itemize}
    \item Implement end-to-end encryption for all patient data transmissions
    \item Deploy database-level encryption for data at rest
    \item Establish field-level encryption for sensitive medical information
    \item Implement secure key management and rotation policies
\end{itemize}

\textbf{API Security \& Network Protection:}
\begin{itemize}
    \item Deploy API gateway with rate limiting and input validation
    \item Implement comprehensive firewall protection and network segmentation
    \item Establish DDoS protection and traffic monitoring
    \item Ensure secure communication protocols across all system components
\end{itemize}

\textbf{AI-Specific Security Measures:}
\begin{itemize}
    \item Develop prompt injection detection and prevention mechanisms
    \item Implement query filtering and sanitization for AI interactions
    \item Establish role-based limitations for AI system access
    \item Deploy monitoring systems for AI security threats
\end{itemize}

\section{Methodology}

\subsection{Lab Reports Summarization Methodology:}
\textbf{Milestone 1: OCR \& NLP Implementation-Testing}

\subsubsection{Optical Character Recognition (OCR)}
We will integrate an OCR pipeline to digitize lab reports in image or PDF format, ensuring compatibility with scanned documents and handwritten notes where applicable.

\textbf{Planned Implementation:}
\begin{itemize}
\item Use the \textbf{Google Cloud Vision OCR API} for high-accuracy text extraction, leveraging Google’s powerful pre-trained models optimized for printed and handwritten text.
\item Enable multi-language recognition (Arabic and English) using Google OCR’s language hints feature for bilingual reports.
\item Perform client-side pre-processing for image enhancement (e.g., noise reduction, skew correction) before sending to the API to improve OCR accuracy.
\item Integrate Google OCR API calls within a secure backend environment, ensuring all data is encrypted in transit and at rest according to HIPAA compliance.
\item Store original scanned lab report images and extracted text securely in the database for reference and audit purposes.
\end{itemize}

\subsection{Health Connect}
\subsubsection{What is Health Connect?}
\begin{itemize}
        \item A built-in Android 14 app (APK) that stores and manages health \& fitness data on the device.
        \item Apps can read, write, and share data after receiving explicit user permission.
        \item Health Connect is packaged with Android 14 as part of the Android system, which means you cannot uninstall it from a device.
\end{itemize}

\subsubsection*{Why Use Health Connect?}
\begin{itemize}
    \item Unified access to multiple types of health data.
    \item Data remains on the device, ensuring privacy.
    \item Permissions Management: Request only the data types required (e.g., READ\_HEART\_RATE, READ\_STEPS).
    \item Interoperability across multiple apps and devices.
\end{itemize}

\subsubsection{Core Components}
\begin{enumerate}
    \item \textbf{Health Connect APK} -- Pre-installed on Android 14 devices; manages permissions \& data storage.
    \item \textbf{Health Connect SDK} -- A library integrated into the app to communicate with the APK via IPC.
    \item \textbf{Client Application} -- The developer’s application that uses the SDK to access approved data types.
\end{enumerate}

\subsubsection{Supported Data Categories}
\begin{itemize}
    \item \textbf{Activity}: running, swimming, cycling, steps.
    \item \textbf{Body Measurement}: weight, BMI, BMR.
    \item \textbf{Cycle Tracking}: menstrual cycles, ovulation test results.
    \item \textbf{Nutrition}: calories, sugar, hydration.
    \item \textbf{Sleep}: sessions, duration.
    \item \textbf{Vitals}: heart rate, blood pressure, oxygen saturation, body temperature.
    \item For more info \href{https://developer.android.com/health-and-fitness/guides/health-connect/plan/data-types}{Health Connect Data Types}
\end{itemize}

\subsection{Security Implementation Methodology:}

The security implementation follows a phased approach spanning three major milestones :

\textbf{Milestone 1: Core Security Foundation (our estimation is 12 weeks/3 months of first semester)}

\textit{Authentication \& Authorization (Weeks 1-3):}
\begin{itemize}
    \item Configure separate realms for different user types (patients, doctors, caregivers)
    \item Implement OAuth 2.0 and OpenID Connect protocols
    \item Deploy Keycloak as the primary Identity and Access Management (IAM) solution
    \item Integrate Ente Auth for multi-factor authentication
    \item Test authentication flows with web interfaces
\end{itemize}

\textit{Database Security \& Encryption (Weeks 4-6):}
\begin{itemize}
    \item Deploy PostgreSQL with built-in encryption capabilities
    \item Integrate HashiCorp Vault for secure key management
    \item Configure database-level and field-level encryption
\end{itemize}

\textit{API Security \& Network Protection (Weeks 7-9):}
\begin{itemize}
    \item Deploy Nginx with security modules for API gateway functionality and reverse proxy
    \item Configure Traefik for automatic SSL certificate management and load balancing
    \item Set up firewall rules using pfSense or OPNsense
    \item Implement automatic TLS encryption using Let's Encrypt certificates
\end{itemize}

\textit{Basic AI Security Implementation (Weeks 10-12):}
\begin{itemize}
    \item Implement query length limits and pattern matching
    \item Create role-based query filtering mechanisms
    \item Integrate OpenAI Moderation API for content filtering
\end{itemize}

\textbf{Milestone 2: Security Enhancement \& Optimization (weeks 13-24)}\\
\textit{Advanced Security Features:}
\begin{itemize}
    \item Integrate Cloudflare for advanced DDoS protection 
    \item Configure HAProxy for advanced load balancing and SSL termination
    \item Establish secure backup and recovery procedures for database
    \item Deploy comprehensive security testing for AI components
    \item Develop custom Python filters for prompt validation
    \item Implement security monitoring and logging systems
\end{itemize}

\textbf{Security Technology Stack:}
\begin{itemize}
    \item \textit{Authentication:} Keycloak, OAuth 2.0, OpenID Connect
    \item \textit{Database:} PostgreSQL with encryption, HashiCorp Vault
    \item \textit{API Security:} Nginx with security modules, Traefik, Cloudflare
    \item \textit{Network Security:} pfSense/OPNsense, Let's Encrypt, HAProxy
    \item \textit{AI Security:} Custom Python filters, OpenAI Moderation API
\end{itemize}




\section{Architecture Overview}
Both the \textbf{web} and \textbf{mobile} apps will connect to a \textbf{shared Express.js backend} via secure REST + WebSocket APIs. This backend centralizes business logic, data processing, and AI integration, ensuring consistent results.  

\noindent\textbf{Data Flow:}  
\[
\text{Frontend (Web/Mobile)} \rightarrow \text{API Gateway} \rightarrow \text{Backend (Express.js — flexible for NestJS)} \rightarrow \text{Database (PostgreSQL + Redis)}
\]

Mobile requests are optimized for smaller payloads, while the web app can fetch more detailed datasets.

\subsection{Web Application Stack}
\subsubsection*{Frontend}
\begin{itemize}
    \item \textbf{Angular} – Structured, TypeScript-based, and scalable for complex healthcare UIs.
    \item \textbf{State Management:} NgRx for predictable handling of patient and real-time data.
    \item \textbf{UI Library:} Angular Material for accessible, responsive components.
\end{itemize}

\subsubsection*{Backend (Shared)}
\begin{itemize}
    \item \textbf{Express.js} – Lightweight, flexible, widely supported.
    \item \textbf{Possible Future Option:} NestJS if a more opinionated, enterprise-ready framework is required later.
    \item \textbf{API:} REST for data operations; WebSockets for real-time vitals and alerts.
    \item \textbf{Security:} JWT + OAuth 2.0 for role-based access, AES-256 encryption for sensitive data.
\end{itemize}

\subsubsection*{Database}
\begin{itemize}
    \item \textbf{PostgreSQL} – Reliable relational database for patient records.
    \item \textbf{Redis} – High-speed caching for frequently accessed health data.
\end{itemize}

\subsubsection*{DevOps}
\begin{itemize}
    \item \textbf{Deployment:} Docker + Kubernetes on AWS/GCP for scaling.
    \item \textbf{CI/CD:} GitHub Actions with automated testing and deployment.
\end{itemize}

\subsection{Mobile Application Stack}
\subsubsection*{Frontend}
\begin{itemize}
    \item \textbf{Flutter} – Single codebase for iOS and Android, delivering native performance and smooth UI for health visualizations.
    \item \textbf{State Management:} Riverpod or Bloc for predictable, testable state flow.
    \item \textbf{UI Kit:} Flutter’s Material \& Cupertino widgets for platform-native experience.
\end{itemize}

\subsubsection*{Backend (Shared with Web)}
\begin{itemize}
    \item Connects to the same Express.js API with \textbf{mobile-optimized endpoints} for reduced payload size.
    \item Real-time data via WebSockets, with throttling to save battery.
\end{itemize}

\subsubsection*{Local Database}
\begin{itemize}
    \item \textbf{SQLite (via Drift)} – Caches essential patient data for offline access.
\end{itemize}

\subsubsection*{Deployment}
\begin{itemize}
    \item Distributed on iOS App Store and Google Play; OTA updates using Flutter’s build tools.
\end{itemize}


\subsection{Justification}
This stack ensures:
\begin{itemize}
    \item \textbf{Security} – Encryption, RBAC, and compliance-ready architecture protect patient data.
    \item \textbf{Scalability} – Modular backend leaves open the option to move from Express.js to NestJS if project complexity grows.
    \item \textbf{Performance} – Optimized payloads ensure fast load times for mobile and detailed analytics for web.
    \item \textbf{Cross-platform parity} – Shared backend guarantees identical AI results and business rules across devices.
    \item \textbf{Developer efficiency} – Popular frameworks (Angular, Flutter, Express.js) enable rapid feature delivery and long-term maintainability.
\end{itemize}

\subsection{Natural Language Processing (NLP) Summarization}

Once OCR extracts the textual content, an NLP module will summarize the results for quick review by medical staff.

\textbf{Planned Implementation:}
\begin{itemize}
    \item Use medical-domain NLP models (e.g., \textbf{BioBERT}, \textbf{MedGPT}) fine-tuned for laboratory and pathology data.
    \item Apply Named Entity Recognition (NER) to detect and highlight important terms such as biomarkers, diagnosis results, and measurement values.
    \item Generate concise summaries while preserving critical clinical details.
    \item Provide a structured output compatible with the FHIR Observation resource format for interoperability.
    \item Store generated summaries alongside the original OCR text in the database for future retrieval, search, and analysis.
\end{itemize}
