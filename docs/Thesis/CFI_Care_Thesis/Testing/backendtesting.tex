\section{Backend Testing Overview}

This section details the automated testing effort for the Node.js backend. The
suite is built on Jest with Supertest for HTTP contract checks. Controllers,
services, HTTP clients (axios), Redis, and PostgreSQL clients are mocked to
isolate behavior where appropriate, while targeted integration tests hit real
Redis and Postgres instances when available. Test data favor minimal synthetic
fixtures to keep runs deterministic.

\subsection{Execution Environment}
The suite runs on Node.js with Jest and Supertest; axios, Redis, and Postgres
clients are typically mocked, while Redis/Postgres integration tests execute
when the backing services are reachable via \texttt{REDIS\_URL\_PATIENTS} and
\texttt{DB\_*}. Network calls are isolated in most suites, IDs and payloads are
fixed for determinism, and database inserts clean up after themselves.

\subsection{Scope}
Coverage spans HTTP route contracts for patients, encounters, binary resources,
and history-graph APIs; service-layer FHIR interactions and caching; Joi-based
validation middleware; Redis caching helpers with TTLs; Postgres connectivity
and timeline graph persistence; and end-to-end workflows linking patient
creation, related-data retrieval, and graph operations.

\subsection{API Route Coverage}
Route tests exercise patient CRUD, TOON export, and related-data bundles;
encounter fetch and `\$everything` retrieval with create-by-id; binary PDF
fetch/create/delete with required-field validation; and history-graph
initialization, head-node creation, CRUD, seeding, and empty-graph handling.

\subsection{Service and Integration Tests}
Patient service specs cover cache-first reads with Redis, FHIR fallbacks, 404
and connectivity errors, create flows (with or without client-specified IDs),
and `\$everything` bundles. Condition service specs target patient-scoped
queries, empty bundles, and create/update with explicit IDs. History graph
service tests remain scaffolded—node/edge CRUD, caching, validation, and
FHIR/EOC integration are outlined but still lack concrete assertions.

\subsection{Test Design and Data}
Positive-path cases walk through patient/encounter/condition creation,
retrieval, and related-data aggregation, including binary uploads and graph
growth. Negative-path cases cover Joi validation failures, cache misses, 404s
from FHIR, connection failures, missing IDs, invalid graph categories, and
empty bundles. Axios and cache helper calls are stubbed per test to keep
contracts deterministic; the graph service uses a mocked pg client. Transient
IDs such as \texttt{node-001} or \texttt{pat-e2e-001} repeat across tests, and
Postgres inserts are cleaned up to avoid residue.

\subsection{End-to-End Workflows}
The patient workflow proceeds as create \textrightarrow{} fetch
\textrightarrow{} add condition \textrightarrow{} related-data retrieval,
asserting state consistency. The history-graph workflow initializes an
EOC/graph, creates the head node, grows child nodes (with updates and deletes),
verifies branching, and exercises cache-aware readbacks, including
invalid-category rejection.

\subsection{Validation and Middleware}
Joi schemas enforce required patient fields, formats, and length constraints
while permitting extra fields. The request-validator middleware is exercised on
both happy-path forwarding and failure-path messaging.

\subsection{Caching and Redis}
Cache helper tests span get/set/delete semantics, TTL handling, error
tolerance, and patient cache invalidation (Redis mocked). Redis integration
tests, when enabled, hit a live instance to confirm CRUD, TTL expiry, and
support for strings, lists, and sets via \texttt{REDIS\_URL\_PATIENTS}.

\subsection{Database Checks}
Postgres smoke tests confirm connectivity, the presence of
\texttt{timeline\_nodes} and \texttt{node\_edges}, and insert/select
round-trips with cleanup. A standalone probe script inspects timeline nodes and
edges to sanity-check graph visualization data.

\subsection{Gaps and Next Steps}
\begin{enumerate}
    \item Add concrete assertions to history graph service integration tests (node/edge
          creation, validation, cache invalidation, FHIR/EOC fallbacks).
    \item Extend end-to-end negative paths for encounters and conditions, aligning status
          codes and error bodies.
    \item Add contract tests to lock TOON export and `\$everything` bundle payload
          shapes.
    \item Document and script external dependencies (Redis, Postgres, FHIR stubs) for
          reliable CI execution.
\end{enumerate}

\subsection{Interpretation of Results}
\begin{itemize}
    \item Core HTTP surface for patients, encounters, binaries, and history graph is
          green, indicating stable contracts at the controller/route layer.
    \item Service-layer caching and FHIR interaction paths are exercised with both cache
          hits and misses; error handling for 404 and connectivity is verified.
    \item Live-environment checks for Redis/Postgres pass when backing services are
          reachable; mark these as conditional (Pass*).
    \item The main gap is the history graph service integration file, which outlines
          scenarios but lacks assertions; adding those will close coverage on graph
          business logic.
\end{itemize}
