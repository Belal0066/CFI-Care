# AI Section — Failure Mode Tables

For each row: how the failure is detected, what the system actually does about it (not what it should do), the user-visible effect, and how it recovers. Every row is sourced from reading the actual handling code — not from a design intention. Where nothing catches a failure, that's stated as plainly as where something does.

See [`SYSTEM_OVERVIEW.md`](SYSTEM_OVERVIEW.md) for the data flow these failures occur in.

## Cross-cutting observation

Every DOC2FHIR adapter (OCR, Mapper, Downstream, HAPI FHIR, Callback) classifies errors by retryability and backs off — a real, consistent resilience pattern. The Clinical AI System's one external-HTTP call (MCP) has none of that: single attempt, catch-and-degrade. If either subsystem is hardened next, that asymmetry is the concrete place to start, not a general "add more error handling" task.
